{{ if not .Values.config.servers -}}
WARNING: no upstream servers are configured.

config.servers is where the upstream Postgres hosts and their connection caps
are declared. With none, a node has nowhere to send a client. There is no
default here on purpose: the numbers are the deployment, and a default would
be a guess that reads like a recommendation.

Clients authenticate with a JWT carried in the password field, so a plaintext

Two limits this chart cannot set for you, both of which decide how many
clients a node can actually hold.

File descriptors: a node holding 100k client connections needs a nofile of
262144, and that is a container runtime setting rather than something a pod
spec can request. Check it on the nodes these pods land on:

  kubectl exec {{ include "pgprox.fullname" . }}-0 -- sh -c 'ulimit -n'

Listen backlog: the proxy asks for 8192 and the kernel trims it to
net.core.somaxconn. The stock 4096 is not enough for a large reconnect burst,
and the overflow reaches a client as a socket that closed with nothing on it.
That sysctl is not on the kubelet's safe list, so setting it in `values.sysctls`
only works on a cluster whose kubelet was started with
--allowed-unsafe-sysctls=net.core.somaxconn. On any other cluster the pod will
not start at all, with SysctlForbidden, which is why the default here is empty.

Draining a node by hand, which is what the preStop hook does automatically:

  kubectl exec {{ include "pgprox.fullname" . }}-0 -- \
    curl -fsS -X POST localhost:{{ .Values.ports.admin }}/v1/drain
