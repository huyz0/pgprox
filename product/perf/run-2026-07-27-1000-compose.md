# Scale run: 1000 connections, compose stack, 27 July 2026

The run that found the quota bug, taken again after it was fixed. The earlier
record, `run-2026-07-27-1000.md`, is a local single-node stack and is kept
because it is what the memory numbers were first compared against.

## What it was

| | |
| --- | --- |
| Connections | 1000 |
| Duration | 30s per phase |
| Workload | `product/perf/workload.yaml` version 3 |
| Seed | 1 |
| Stack | compose: 3 proxy nodes, a primary, 2 replicas, a sidecar each |
| Command | `scripts/scale.sh 1000` |
| Logging | info (the default; `SCALE_LOG=debug` is for investigating, not measuring) |
| Machine | 20 cores, 31 GB, WSL2 6.18.35.2, PostgreSQL 17 in containers |

Workload version 3, so half the statements now go through the extended
protocol with a named prepared statement. Every number below is therefore
about a different workload than the version 2 record, and they should not be
subtracted from each other.

The node under test speaks plaintext, which the scale override arranges. What
TLS costs is measured separately and is small: see M7.21.

## The hop, at matched load

Sixty connections on both sides, which is the upstream cap.

| | Proxy | Direct | Added |
| --- | --- | --- | --- |
| p50 | 4,091us | 3,740us | **351us** |
| p99 | 111,199us | 108,699us | **2,500us** |

The p50 is inside the roadmap's 1ms. The p99 is 2.5ms over a base of 110ms,
which is inside this stack's run-to-run variance: the same comparison an hour
earlier came out at minus 500us, and two TLS nodes in the M7.21 measurement
differed from each other by 20ms. The honest statement is that the hop is a
third of a millisecond at p50 and that this stack cannot resolve it at p99.

## At a thousand connections

| | |
| --- | --- |
| Transactions | 8,606 |
| Refused with 53300 | 9 |
| Other errors | 0 |
| p50 | 1,629,999us |
| p99 | 21,059,999us |
| RSS idle | 8.9 MB |
| RSS under load | 34.2 MB |
| RSS per connection | 25,919 bytes |
| Upstream connections | 40 of 60 allowed |

**40 of 60, where every previous run was pinned at 10.** That is M7.33: no node
in the fleet had ever granted a quota lease, because no node was in its own
membership view, so each sat on its guaranteed share of a sixth of the cap.
Ten of sixty is what the whole fleet could use; forty is this node's guarantee
plus the whole free pool.

The nine refusals are the node saying 53300 to clients it cannot serve, which
is correct: a thousand clients with this workload's think time offer several
times what the database can do, the wait exceeds the acquire timeout, and the
client is told to retry. `scripts/scale.sh` reports those separately from
failures for that reason.

The second-long percentiles are the database's queue, not the proxy's.

## Memory

25,919 bytes per connection, against 21,467 for the version 2 workload on the
local stack. The extended protocol is the difference: a session that prepares
statements holds a name map, and the proxy holds one per upstream connection
as well. Extrapolated to 100k that is 2,471 MB against a target of 500, and it
is a slope rather than a prediction.

The roadmap's targets stay exactly as written and stay unmet until a run at
100k produces them.
