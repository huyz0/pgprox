# Scale run: 1000 connections, 27 July 2026

The first run at a thousand connections, and the one every later run compares
against.

## What it was

| | |
| --- | --- |
| Connections | 1000 |
| Duration | 30s per phase |
| Workload | `product/perf/workload.yaml` version 2 |
| Seed | 1 |
| Stack | local (`scripts/scale.sh 1000 --local`) |
| Machine | 20 cores, 31 GB, WSL2 6.18.35.2, PostgreSQL 18.4 |

Local rather than compose, because Docker Desktop was down on this machine.
One node, one Postgres, no replica, everything on the loopback. That flatters
network latency and says nothing about replica routing, and it is the same
proxy code path in every other respect.

## The hop, at matched load

Sixty connections on both sides, which is the upstream cap and therefore the
most work the proxy will ever put on the database at once.

| | Proxy | Direct | Added |
| --- | --- | --- | --- |
| p50 | 2,637us | 2,289us | **348us** |
| p99 | 30,999us | 26,699us | **4,300us** |

Both runs completed the same amount of work with no errors, so the difference
is the hop rather than a difference in what was attempted.

The p50 is inside the roadmap's target of under 1ms added and the p99 is four
times over it. Neither is the milestone's condition, which is stated at 100k
connections and is not met by anything here; they are recorded so the next run
has something to move.

## At a thousand connections

| | |
| --- | --- |
| Transactions | 16,252 |
| Errors | 0 |
| Throughput | 542/s |
| p50 | 1,149,999us |
| p99 | 7,019,999us |
| RSS idle | 7.4 MB |
| RSS under load | 27.9 MB |
| RSS per connection | 21,467 bytes |
| Upstream connections | 50 of 60 allowed |

The second-long percentiles are the database's queue, not the proxy's. A
thousand clients with this workload's think time offer roughly 3,600
transactions a second; the primary on this machine serves about 550 of them
with 50 backends busy, and the rest wait. The proxy's own CPU sat under half a
core throughout.

That distinction is the point of running both phases. The first version of
this script subtracted a sixty-connection baseline from a thousand-connection
run and reported that the proxy added 1.18 seconds. It does not: it adds
348us, and it holds a thousand clients in front of a database that can only
serve fifty at a time without dropping any of them.

## Memory

21,467 bytes per connection extrapolates to 2,047 MB at 100k, against a target
of 500. It is a slope rather than a prediction: it carries the process's fixed
7.4 MB spread across a thousand connections, and the shape of the cost at a
hundred thousand is dominated by things a run this small cannot show. The
reason to record it is the comparison with the next run.

The roadmap's targets stay exactly as written and stay unmet until a run at
100k produces them.
