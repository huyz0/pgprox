Without a pooler, every app node needs a pool on every cluster

An illustrative fleet: 300 application nodes, thread per request, against 100 Postgres clusters holding one database per tenant.

30,000 claims 300 application nodes × 100 clusters, each pair needing its own share of a cap
1.6 connections each node's fair share of a cluster: 500 ÷ 300, and it cannot borrow from a node it cannot see
200 wanted what one node needs at once, because a thread-per-request worker holds a connection for the whole request

So the pool cannot exist. The app connects, runs a statement, and drops the connection seconds later, paying TCP, TLS, SCRAM and a backend process fork on the request path.

Numbers are an illustration of the shape, not a measurement. What does not change with the numbers is the multiplication: connection demand grows with nodes × clusters, and each cluster's cap does not.
